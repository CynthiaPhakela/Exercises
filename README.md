# SQL Practice Exercises – BrightLearn Data Analytics

This repository contains six SQL practice exercises completed as part of the **BrightLearn Data Analytics** programme. All SQL solutions were written and validated using **Databricks SQL**, providing hands-on experience with writing, testing, and debugging SQL queries in a cloud-based analytics environment. The exercises progressively build foundational and intermediate SQL skills that are essential for data analysis, reporting, and business intelligence. 

## Exercise 1 – SQL Fundamentals: SELECT & Filtering

This exercise introduced the fundamental building blocks of SQL by focusing on **SELECT**, **WHERE**, **DISTINCT**, **ORDER BY**, and **LIMIT** statements. The objective was to develop confidence in retrieving data, filtering records based on business rules, sorting results, and selecting specific columns from a dataset. The assignment was completed by writing SQL queries by hand and drawing the expected outputs. This exercise established the foundation required for more advanced SQL concepts.

## Exercise 2 – SQL Aggregate Functions & Operators

This exercise expanded on the fundamentals by introducing aggregate functions and logical operators commonly used in business reporting. SQL queries were developed using **COUNT**, **SUM**, **AVG**, **MIN**, **MAX**, **GROUP BY**, **HAVING**, **DISTINCT**, **BETWEEN**, **IN**, **AND**, **OR**, and **ORDER BY**. The work required handwritten SQL solutions and manually drawn output tables. The exercise strengthened analytical thinking by demonstrating how SQL can summarise and filter large datasets to generate meaningful business insights. 

## Exercise 3 – SQL Joins

This exercise focused on combining data across multiple related tables using **INNER JOIN**, **LEFT JOIN**, and **FULL OUTER JOIN**. Real-world business scenarios required identifying relationships between datasets and selecting the appropriate join type to produce accurate results. Unlike the earlier exercises, the SQL queries were intended to be executed and validated in a SQL environment, with **Databricks SQL** used to test each solution and verify the expected output. This exercise strengthened relational database skills and improved understanding of how multiple datasets interact in real business environments. 

## Exercise 4 – SQL UNION & UNION ALL

This exercise explored methods of combining result sets using **UNION** and **UNION ALL**. The activities demonstrated the difference between removing duplicate records and preserving all rows when merging datasets from multiple tables. Using a fictional banking dataset, SQL queries were developed to consolidate customer, product, transaction, and operational information while understanding the performance and practical use cases of each operator. All solutions were validated using **Databricks SQL**, reinforcing correct syntax and expected outputs while improving proficiency in combining datasets efficiently. 

## Exercise 5 – SQL NULL Functions

This exercise focused on handling missing or incomplete data using SQL NULL-handling functions such as **COALESCE()**, **IFNULL()**, and **ISNULL()**. Practical business scenarios required replacing missing values with meaningful defaults, identifying NULL records, performing calculations on incomplete datasets, and ensuring clean, reliable outputs for reporting. Although the assessment required handwritten SQL solutions, every query was checked and validated in **Databricks SQL** to confirm that NULL values were handled correctly and that the expected results were produced. This exercise highlighted the importance of data quality and completeness in analytics. 

## Exercise 6 – SQL Date Functions

The final exercise concentrated on working with dates and time-based data using functions such as **DAYNAME**, **MONTH**, **MONTHNAME**, **YEAR**, **DATEDIFF**, **DATEADD**, **DATE_TRUNC**, and **LAST_DAY**. Through more than twenty practical scenarios, SQL queries were developed to extract date components, calculate date differences, manipulate date values, and prepare time-based information for business reporting. Every solution was executed and verified in **Databricks SQL**, ensuring compatibility with the Databricks SQL syntax and reinforcing practical skills used in real-world analytical environments.
